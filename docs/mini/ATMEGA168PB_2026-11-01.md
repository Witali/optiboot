# ATmega168PB profile and software validation

Date: 2026-11-01. ATmega168PB is now a native device profile in the Mini
generator, with FlashRead256, Compact and Full editions. This extends the
earlier 38-device matrix to 39 devices and 79 edition/device combinations.
All new validation is software-only; no board, serial port or ISP programmer
was accessed.

## Device map

The profile was checked against Microchip's
[ATmega48PB/88PB/168PB datasheet, DS40001909B](https://ww1.microchip.com/downloads/aemDocuments/documents/MCU08/ProductDocuments/DataSheets/ATmega48PB-88PB-168PB-DataSheet-DS40001909B.pdf)
and the installed AVR-GCC device header. Relevant datasheet sections are 28.8.15
(Boot layout), 28.8.10 (signature-row reads), 29.3/29.5 (signature/page size)
and the register summary.

| Property | ATmega168PB |
|---|---|
| Device signature | `1E 94 15` |
| Flash / EEPROM / SRAM | 16384 / 512 / 1024 bytes |
| Flash page / erase group | 128 / 128 bytes |
| SRAM end | `0x04FF` |
| Minimum hardware Boot area | 128 words = 256 bytes |
| USART0 data-space registers | UCSR0A/B/C `0xC0/C1/C2`; UBRR0L/H `0xC4/C5`; UDR0 `0xC6` |
| MCUSR / WDTCSR / SPMCSR | `0x54` / `0x60` / `0x57` in data space |
| EECR / EEDR / EEARL / EEARH | `0x3F` / `0x40` / `0x41` / `0x42` in data space |
| Signature-row access | SIGRD + SPMEN, immediate LPM at byte offsets 0/2/4 |
| Profile maximum clock | 20 MHz, subject to the datasheet voltage grade |

The required peripheral map matches the existing modern USART0 path. Both
installed compilers define `__AVR_ATmega168PB__` directly; the build uses native
`-mmcu=atmega168pb`, without substituting another part. BOOTSZ is in extended
fuse bits 2:1 and BOOTRST in bit 0 on this MCU. The generator records the Boot
size bits and addresses; it does not program any fuse or lock byte.

## Editions

At 16 MHz, external crystal, 115200 baud:

| Edition | Boot reservation | Code and footer | Padding | Byte origin | Application bytes |
|---|---:|---:|---:|---|---:|
| FlashRead256 | 256 B | 253 B | 3 B | `0x3F00` | 16128 |
| Compact | 512 B | 510 B | 2 B | `0x3E00` | 15872 |
| Full | 1024 B | 635 B | 389 B | `0x3C00` | 15360 |

All editions support Flash upload and verification. Compact/Full also include
EEPROM transfers, UNIVERSAL signature queries, reset-flag parity and the
application SPM service with Boot-write guards. Full adds sign-on,
SET_PARAMETER packet handling and read-only fuse/lock queries. FlashRead256
returns its build-profile signature constants; Compact/Full automatically use
the audited hardware signature-row path.

## Results

* All 18 new clock/edition images built and executed successfully: external
  8/10/12/16/20 MHz and internal RC at 8 MHz, for each of three editions.
* All application Flash bytes were written/read/verified in each edition.
  Compact/Full additionally transferred every EEPROM byte. Boot contents stayed
  unchanged.
* Native Clang and AVR-GCC produced byte-identical binaries for all three
  nominal builds; both application SPM header compile probes passed.
* Actual AVRDUDE 8.0-arduino.1 passed complete application Flash transfers and
  normal verification for all three editions, plus complete EEPROM transfers
  for Compact/Full, through loopback instruction models.
* The Arduino upload audit passed ordinary even/odd-length and padded HEX
  uploads. Uploading the loader's own Boot HEX was rejected before any SPM.
* The full regression suites include this device in generic modern-AVR memory
  tests, signature-row tests, all Boot-size builds, all 65 Compact/Full reset
  profiles, all 57 hardware-Boot application SPM profiles, and the 14-device
  FlashRead256 tests at both reference clocks. A new generator regression
  independently checks `1E 94 15`, native profile selection and all three layouts.
  All 125 instruction-model tests and 17 generator tests passed (142 total).

The existing 38 device records, shared assembly/builders, and their device/UART
includes match the previous firmware inputs. Existing historical image/hash
fixtures are retained unchanged.

The [matrix CSV](ATMEGA168PB_MATRIX_2026-11-01.csv) lists every new image's
clock, baud, Boot layout and SHA-256. The
[sanitized results](ATMEGA168PB_RESULTS_2026-11-01.json) contain memory,
host-interoperability and cross-compiler outcomes. The earlier reports retain
their original counts and source revisions; their binary fixtures were not
replaced to add this profile.

An initial host test encountered a WSL localhost-forwarding connection failure
before any target input. The shared runner now allows listener startup and
backs off when retrying unopened connections. It never restarts a host process
after target input begins. The final host run passed all three profiles.

## Build and reproduce

Run from `optiboot/bootloaders/optiboot/`:

```sh
python3 generate_firmware.py atmega168pb flashread256 16MHz
python3 generate_firmware.py atmega168pb compact 16MHz
python3 generate_firmware.py atmega168pb full 16MHz
make mini_test
python3 verify_editions.py --mcu atmega168pb --all-clocks --smoke --stress --output output/168pb-validation
python3 verify_toolchains.py --mcu atmega168pb --output output/168pb-toolchains
python3 verify_avrdude.py --mcu atmega168pb --avrdude /path/to/avrdude --config /path/to/avrdude.conf --output output/168pb-avrdude
python3 verify_arduino.py --mcu atmega168pb --avrdude /path/to/avrdude --config /path/to/avrdude.conf --timeout 6 --output output/168pb-arduino
```

Physical clock accuracy, UART electrical behavior, DTR reset, watchdog duration,
SPM/EEPROM completion timing, silicon errata and power-loss recovery still need
board-level validation. These results do not qualify a physical ATmega168PB.
