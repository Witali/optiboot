# Хронология изменений прошивки Optiboot Mini

Все перечисленные этапы исследовались **28 октября 2026 г.** Ссылки указывают на файлы внутри этого архива; порядок соответствует переписке и последовательности сохранённых сборок. Размер *занято* = машинные инструкции + 2 байта версии, **без заполнения `0xFF`**. Файлы `.bin/.hex` на каждом этапе обычно покрывают полный boot-раздел **512 байт**.

## Изменения, которые обязательно сохранить в последующих версиях

1. **Watchdog:** первый 410-байтный вариант нельзя прошивать из-за ошибки `WDE`; для 1 с = `0x0E`, для короткого WDT после LEAVE = `0x08` (при обычном WDTON fuse).
2. **Flash page safety:** `fill temporary hardware buffer` → `validate CRC_EOP` → `page erase` → `page write` → `RWW enable`; не переносить erase перед проверкой EOP. Перед Page Write проверять 128-байтное выравнивание адреса (`PCWORD=0`).
3. **EEPROM safety:** сначала получить 1..16 байт, проверить EOP и диапазон, только затем записать; выдержать время `EECR.EEMPE→EEPE`, дожидаться `EEPE=0`, учитывать согласование со SPM.
4. **Stack:** EEPROM временно хранится на стеке. `SP` должен быть корректен после reset; оценивать вложенные RCALL/RET и стек по отношению к ISR (прерывания отключены).
5. **UART:** 16 MHz, U2X0=1, UBRR0L=16 → 117647 бод (ошибка +2.12%); FE0 влияет на WDT. Это не аппаратно подтверждённая связь.
6. **STK500v1:** не путать `CRC_EOP=0x20` с контрольной суммой. Целостность прошитого образа обеспечивает последующая операция чтения и verify.
7. **Оригинальная сборка несопоставима по функциям:** отличие от официального 474-байтного HEX не является чистой экономией ассемблера при feature parity: оригинал содержит LED и вызываемый приложением SPM-сервис. Оригинал с такими же отключёнными функциями в данной работе отдельно не собран.
