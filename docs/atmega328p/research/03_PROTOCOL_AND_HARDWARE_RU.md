# Текущий интерфейс и аппаратные ограничения — 512 байт

Подробный аудит **без сокращений**: `CURRENT/AUDIT_RU.md`. Эта памятка нужна, чтобы следующему агенту не пришлось угадывать, что означает слово «совместимость».

## Аппаратная цель

- MCU **ATmega328P** (не ATmega328PB, не 4809), 16 MHz, UART0 8N1, `-b 115200` (UBRR=16 с U2X0 даёт фактические ~117647 бод).
- Boot-раздел 256 слов = **512 байт** (`0x7E00...0x7FFF`), BOOTRST/BOOTSZ должны быть выставлены под эту схему. Текущее расположение версии: последние 2 байта `03 08`.
- Страница Flash 64 слова / **128 байт**, EEPROM **1024 байта**, SRAM содержит рабочий стек. Дополнительного SRAM-буфера для Flash нет. Для EEPROM по 16 байт используется стек `PUSH/POP`.
- После WDT/SW reset причина запуска определяется через MCUSR; boot запускается прежде всего по внешнему reset. Физическую авто-перезагрузку с DTR/RTS нужно испытать отдельно.

## Поддержка STK500v1 для нормального avrdude `-c arduino`

| Команда | Поддержка в текущей прошивке |
|---|---|
| `0x30 STK_GET_SYNC` | `14 10` при корректном EOP |
| `0x41 STK_GET_PARAMETER` | SW_MAJOR=8, SW_MINOR=3, остальные 3 |
| `0x40 STK_SET_PARAMETER` | Корректно принимает два поля, ACK; **не настраивает** оборудование |
| `0x42 STK_SET_DEVICE` / `0x45 STK_SET_DEVICE_EXT` | Принимает поля, ACK, параметры не применяет |
| `0x50 STK_ENTER_PROGMODE` | ACK, без особого переключения режима |
| `0x51 STK_LEAVE_PROGMODE` | ACK, затем переход к приложению через WDT |
| `0x55 STK_LOAD_ADDRESS` | 16-битное **словное** значение → байтовый адрес `*2` для Flash и EEPROM в режиме `-c arduino` классического AVR |
| `0x64 STK_PROG_PAGE`, `'F'` | От 2 до 128 Б, чётная длина, старт страницы на границе 128 Б, запись SPM hardware buffer с проверкой EOP до erase |
| `0x74 STK_READ_PAGE`, `'F'` | Чтение Flash LPM; младший байт длины, нуль означает 256 Б |
| `0x64 STK_PROG_PAGE`, `'E'` | 1..16 Б, временная буферизация на стеке, EOP проверяется до записи, диапазон EEPROM проверяется |
| `0x74 STK_READ_PAGE`, `'E'` | Чтение EEPROM EERE, диапазон 0..1023 |
| `0x56 STK_UNIVERSAL` | Только четыре безопасных READ-only операции fuse/lock; ответ `14 <byte> 10` |
| `0x75 STK_READ_SIGN` | Постоянная сигнатура ATmega328P `1E 95 0F` |

`UNIVERSAL` поддерживает тела: `50 00 00 00` = low fuse, `58 08 00 00` = high fuse, `50 08 00 00` = extended fuse, `58 00 00 00` = lock bits. Сигнатура через UNIVERSAL в текущей 512-байтной прошивке НЕ реализована; она доступна через `READ_SIGN (0x75)`.

## Известные отклонения от полного AVR061 — НЕ объявлять как «полное соответствие»

- `STK_GET_SIGN_ON (0x31)` не выдаёт строку `AVR STK`, отвечает только ACK.
- `STK_CHIP_ERASE (0x52)` и ISP chip erase через UNIVERSAL **не выполняют реальное стирание**, хотя ACK возможен. `avrdude -e` **не использовать**.
- UNIVERSAL не исполняет произвольные четыре ISP-байта; не поддерживаются программирование fuse/lock, универсальное чтение сигнатуры.
- `READ_FUSE`, `READ_LOCK` отдельными командами не добавлены. `SET_PARAMETER` не меняет реальные параметры.
- Старший байт длины read/write игнорируется. В частности, запрос длины 0x0102 READ_PAGE будет интерпретирован как 2 байта; значения за ожидаемыми диапазонами не поддерживаются.
- Неизвестные команды обычно ACK; при неверном EOP используется watchdog-reset, а не все стандартные ответы ошибок STK500.
- Неподдерживаемый тип памяти трактуется как Flash. Некорректные адреса Flash-записи отклоняются WDT-reset, что строже, чем некоторые режимы оригинального Optiboot.
- `CRC_EOP (0x20)` — только терминатор, **не CRC**; всегда выполнять verify чтением назад.
- `0x56` вернёт `00` для многих неподдерживаемых функций, и клиент не должен интерпретировать этот ACK как подтверждение реального выполнения SPI-команды.

## Проверенный аппаратный алгоритм в исходниках (программная проверка, не реальный кремний)

1. **SPM:** аппаратный temporary page buffer заполняется инструкциями SPM; `SPMCSR=0x01` → `SPM`. После проверки EOP — `0x03→SPM` erase, busy wait, `0x05→SPM` write, busy wait, RWW re-enable `0x11→SPM`.
2. **EEPROM:** перед операцияцией ждать окончание SPM; `EEARH/L`, `EEDR`, `EECR` с EEPM[1:0]=00; `SBI EEMPE` и `SBI EEPE` укладываются в окно четырёх тактов; ответ после завершения записи.
3. **Fuses:** `SPMCSR=0x09` (BLBSET|SPMEN), `LPM` с `Z=0..3`; только чтение.
4. **UART:** 8N1; FE0 обнаруживается, WDT на неверных кадрах не сбрасывается.
5. **WDT:** причины MCUSR, конфигурация 1с/16мс, WDR при приёме.

**Все свойства выше выведены из datasheet и проверены ограниченным интерпретатором/проверками инструкций; аппаратная верификация обязательна.**
