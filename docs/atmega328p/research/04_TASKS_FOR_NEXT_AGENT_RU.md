# Техническое задание следующему агенту: продолжить Optiboot Mini

## Что уже сделано и что **не** надо начинать заново

- Рабочая гипотеза: Optiboot STK500v1 subset для **ATmega328P, 16 MHz, UART0**.
- Последний исходник **`CURRENT/optiboot_328_verified.S`**, образ **512 байт, занято все 512**, не путать с прежними 508/498/358 Б.
- EEPROM read/write 1024 Б, записываемыми блоками 1..16 Б в SRAM-стеке, проверка EOP до записи; Flash через временный аппаратный буфер SPM без SRAM-страницы; UNIVERSAL только fuse/lock READ.
- Последние проверки программные, не аппаратные. В архиве сохранены Python интерпретатор AVR и тесты; всё можно запустить без внешнего MCU, когда есть clang AVR backend, llvm-objcopy.

## Приоритетные задачи

**P0 — сохранить работоспособность и проверить на железе:**

1. Обязательно сверить режим WDT (`WDE`, reset reason), SPM `Z/PCWORD=0`, EEPROM `EEMPE→EEPE`, стек, boot-lock с datasheet; не убирать проверки ради экономии байтов, не найдя эквивалентного безопасного решения.
2. Испытать настоящий ATmega328P через USB-UART и **ISP для восстановления**, с сохранённым исходным bootloader. Без аппаратных испытаний не объявлять production-ready.
3. При изменениях каждый раз делать `CURRENT/build.py` + полный набор тестов, сравнивать с предыдущей прошивкой на уровне реальных AVR-инструкций; при переполнении 512 Б сборка должна падать.

**P1 — улучшить безопасную совместимость STK500v1:**

4. Приоритетная ошибка протокола: **игнорирование старшего байта длины**. Лучше безопасно отвергать неподдерживаемые длины, чем молча выполнить меньше/больше, сохраняя 512-байтный лимит.
5. Некорректные команды `CHIP_ERASE`, `UNIVERSAL` (ISP chip erase, запись fuse/lock) сейчас могут отвечать ACK/no-op. Подумать о корректном отказе **без разрушения синхронизации** для настоящего avrdude.
6. Недопустимые типы памяти нужно отклонять безопасно, не выдавая Flash как несуществующую EEPROM.
7. При желании расширить диагностику — оценить `UNIVERSAL` для сигнатуры/OSCCAL, но в первую очередь не терять EEPROM и нормальный avrdude.

**P2 — оптимизировать размер без ухудшения функций:**

8. Исследовать повторное использование регистров, комбинирование входа/выхода EEPROM, перестановку обработчиков для компактных `BRxx`, общее ожидание SPM/EEPE, экономичные проверки длины и страницы. Учитывать, что по AVR **любая инструкция 2/4 байта**, а поздние относительные переходы могут изменить компоновку.
9. Сравнивать по *одинаковой функциональности*; официальный 474-байтный BIN содержит LED и app-callable SPM, которых у нас нет.
10. Желательный результат — **появление реального свободного места (например, 10–30 Б)** для усиления протокольной защиты, а не добавление бесполезных команд.

## Условия приёмки для следующего изменения

- `.S` компилируется, `.o` без незакрытых релокаций; `.bin` длина 512 байт, `.hex` расположен `0x7E00..0x7FFF`, версия `03 08` в конце.
- На корректных командах проходит регрессия с прежней версией и официальным HEX там, где функциональность общая.
- Тесты: полная 1К EEPROM запись/чтение, пакет с неверным EOP, обрыв пакета, выход за диапазон, Flash write/read включая последнюю страницу приложения, fuse/lock reads, WDT/FE0, проверка тактовых окон.
- **Любая новая команда**: описать формат входа/выхода, поддержку со стороны avrdude и какие случаи намеренно не поддерживаются.
- Нельзя заявлять полную AVR061, если она не реализована. Отдельно документировать риск питания во время физической Flash/EEPROM записи.
