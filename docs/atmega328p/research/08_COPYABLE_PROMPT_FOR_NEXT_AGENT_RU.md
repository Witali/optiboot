# Краткий промпт для передачи следующему агенту

Продолжай инженерную разработку компактного загрузчика **Optiboot Mini для ATmega328P, 16 MHz, UART0 115200, boot-раздел 512 байт, STK500v1 subset**. Текущий проверенный программно исходник и HEX: `CURRENT/optiboot_328_verified.S`, `.hex` — **510 Б кода + 2 Б версии = 512/512**. Это не Micronucleus Block64, не путать MCU/протоколы.

**Прочти сначала** `00_START_HERE_RU.md`, `02_CHANGELOG_HISTORY_RU.md`, `03_PROTOCOL_AND_HARDWARE_RU.md`, `CURRENT/AUDIT_RU.md` и `04_TASKS_FOR_NEXT_AGENT_RU.md`. В архиве есть все исторические ZIP, дополнительные эксперименты, Python эмулятор, тесты, diffs, upstream reference, SHA256.

Важные технические результаты: Flash пишется через временный внутренний аппаратный SPM-буфер без SRAM страницы, EOP проверяется до стирания; EEPROM 1024 Б read/write по 1..16 Б, временный буфер на стеке, EOP проверяется до записи; `UNIVERSAL 0x56` исполняет только четыре чтения fuse/lock; правильные watchdog 0x0E/0x08, UART FE0, Flash Page Write только на границе 128 Б (`PCWORD=0`).

**Особая осторожность:** исходная 410 Б версия сломана из-за WDT; потоковая 402 Б рано стирала Flash; 508 Б не проверяла `Z` Page Write; текущая 512 Б это исправляет. Все тесты — собственный ограниченный программный интерпретатор. НЕТ аппаратного теста на реальном ATmega328P. AVR061 не полностью поддержан: `CHIP_ERASE` ACK-no-op, `GET_SIGN_ON` ACK-only, high byte length игнорируется, неизвестные memtype трактуются как Flash. `CRC_EOP` — не CRC. Не использовать `avrdude -e` через этот bootloader.

**Задача:** продолжить оптимизацию размера без потери EEPROM, Flash, fuse/lock reads и надёжности, освободить место под корректную проверку старшего байта длины и честные ответы неподдерживаемым командам. После каждого изменения реально собрать HEX и запустить весь набор `bash RUN_CURRENT_TESTS.sh`, сохранить логи и SHA256, сравнить ответы с оригиналом там, где семантика общая, и НЕ объявлять аппаратную надёжность без платы и ISP-восстановления.
