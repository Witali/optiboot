# Как воспроизвести сборку и тесты из архива

## Инструменты

- Python 3.x;
- `clang` с backend AVR (`clang -target avr -mmcu=atmega328p`);
- `llvm-objcopy`, `llvm-objdump`, `readelf`.
- В текущей сборке GNU AVR-LibC не нужен (все I/O регистры заданы константами в `.S`).
- `avrdude` нужен только для будущих аппаратных испытаний, в программных тестах не требуется.

## Команда из корня распакованного архива

```bash
bash RUN_CURRENT_TESTS.sh
```

Либо вручную:

```bash
cd CURRENT
python3 build.py
python3 test_eeprom.py
python3 test_universal.py
python3 test_differential_upstream.py
python3 test_strict_datasheet.py
python3 test_protocol_limits.py
```

Скрипт `build.py` проверяет символ `_code_end`, размер машинного кода <= 510 Б, фиксированную длину образа 512 Б, версию `03 08` в конце и отсутствие внешних релокаций. Он пишет `.o/.bin/.hex` рядом с исходником. **Уже собранные бинарники имеются**; текущее переполучение проверено по SHA256.

В `TEST_RECHECK_2026-10-28.txt` записаны реальные результаты повторного запуска тестов при подготовке этого архива, включая контроль совпадения HEX/BIN. Дополнительно полные старые журналы сохранены в `CURRENT/test_all.log` и по этапам.

## Формат

- `.S` — компилируемый ассемблер;
- `.hex` — Intel HEX, содержит адреса `0x7E00..0x7FFF`;
- `.bin` — сырые 512 Б без адресов: **нельзя записывать его по адресу 0x0000**;
- `.o` — объект LLVM/AVR, сохранён для воспроизводимости;
- `upstream_reference.bin` — эталонный оригинальный Optiboot для дифференциальных тестов;
- `TEST_RECHECK_2026-10-28.txt` и `SHA256SUMS.txt` — проверка сборки и содержимого передачи.

## Сверка архива

`SHA256SUMS.txt` содержит SHA256 каждого файла в дереве (кроме самого списка). В GNU-системах:

```bash
sha256sum -c SHA256SUMS.txt
```

Для подлинного независимого теста нужен реальный ATmega328P и ISP-программатор; см. `06_HARDWARE_TEST_PLAN_RU.md`.
