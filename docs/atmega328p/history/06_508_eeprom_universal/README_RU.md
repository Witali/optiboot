# Optiboot Mini: Flash + EEPROM R/W + UNIVERSAL fuse/lock, ATmega328P

**28 октября 2026 года. Экспериментальная прошивка для ATmega328P / Arduino Uno, 16 МГц, UART0 115200 8N1. Аппаратные испытания не проводились.**

|---|---:|---:|

Образ в файлах `.bin/.hex` занимает всю секцию `0x7E00..0x7FFF` (512 Б, заполнение свободных 4 Б равно `FF`; два байта версии `03 08` расположены в конце).

## Какие функции добавлены к прошлой версии

`STK_UNIVERSAL=0x56` принимает 4-байтовую ISP-команду с последующим EOP (`0x20`) и отвечает `STK_INSYNC`, **одним байтом результата**, `STK_OK`.

| Тело UNIVERSAL (4 байта) | Результат | Z-адрес при LPM |
|---|---|---|
| `50 00 00 00` | Low fuse | `0x0000` |
| `58 00 00 00` | Lock bits | `0x0001` |
| `50 08 00 00` | Extended fuse | `0x0002` |
| `58 08 00 00` | High fuse | `0x0003` |

Для указанных четырёх комбинаций opcode1/opcode2 третье и четвёртое поле ISP игнорируются (обычно нули). Все остальные команды возвращают `0x00`, ничего не программируя. В частности, **нет исполнения произвольных ISP-команд, программирования fuse-битов, записи lock-битов, Chip Erase или отдельного чтения сигнатуры через `0x56 30...`**. Последнее уже поддерживается через стандартную `STK_READ_SIGN=0x75`, которая возвращает `1E 95 0F`.

Критический аппаратный участок:

```asm
    clr  r31             ; Z = 0..3
    ldi  r16,0x09        ; BLBSET|SPMEN
    out  0x37,r16        ; SPMCSR
    lpm  r16,Z           ; читать fuse/lock через LPM в пределах временного окна
```

Это документированный способ чтения fuse/lock из программы ATmega328P. **SPM используется только для Flash-программирования**, а fuse/lock читаются командой `LPM`.

## Как удалось уместить добавление

1. **Убрали отдельный EEPROM SRAM-массив**: байты принимаются через `PUSH`, после проверки `CRC_EOP` извлекаются через `POP` в обратном порядке. Вычисленный `EEPROM byte end` адрес уже находится в Z-регистре; запись производится от конца блока к началу. Это уменьшило код на **12 байт** на промежуточном этапе, не отменяя проверку EOP перед записью. В стеке всё равно временно используются до 16 байт RAM — это не «без RAM вообще».
2. Выделили общую процедуру ожидания завершения SPM; EEPROM вызывает уже существующую `wait_spm` (вместо второго такого же цикла).
3. Для команды `0x64` заменили проверку типа памяти на прямой `CPI` + `BREQ` без промежуточного `MOV` и `RJMP`.
4. Упростили `SET_PARAMETER`, а обработчики с уже принятыми данными переводим на общий `verify_eop`.
5. Селекторы fuse/lock формируются флагом `T` через `BST`/`BLD`, без дополнительного регистра-счётчика.
6. Перед каждой записью EEPROM после ожидания `EEPE=0` записываем `EECR=0` одной инструкцией `OUT` вместо двух `CBI EEPM0/EEPM1`. В этом загрузчике прерывания выключены, и обнуление `EECR` безопасно для собственного протокола записи.
7. Для чтения EEPROM ожидание `EEPE` перенесли за пределы цикла чтения байтов (однократно перед блоком).

Остались: полная настройка UART (включая UCSR0C), обработка WDRF/EXTRF/POR, аппаратный WDT, проверка кадрирования UART, защита от некорректной длины и выходов EEPROM за пределы `0x000..0x3FF`, защита boot-раздела Flash от перезаписи.

## Соответствие STK500v1 / avrdude

В дополнение к `0x56` реализованы `GET_SYNC`, `GET_PARAMETER`, `SET_PARAMETER` (правильный приём двух байтов, фактически игнорируется), `SET_DEVICE`, `SET_DEVICE_EXT`, `ENTER_PROGMODE`, `LEAVE_PROGMODE`, `LOAD_ADDRESS`, `PROG_PAGE`/`READ_PAGE` для Flash и EEPROM, `READ_SIGN`.

- Flash: запись до 128 Б (чётная длина), чтение блоками; аппаратный SPM page buffer без SRAM-страницы.
- EEPROM: запись 1..16 Б, чтение до 256 Б, проверка границ. Перед записью проверяется EOP; запись всей EEPROM **не атомарна относительно пропадания питания**.
- `LOAD_ADDRESS` использует *словный* адрес, преобразуя его в байтовый `×2`, как делает `avrdude -c arduino` для классических AVR. В EEPROM отдельный нечётный стартовый адрес через эту схему недоступен, однако данные нечётных адресов попадают в 16-байтовые блоки.
- `CRC_EOP=0x20` — **не CRC** и не проверяет полезную нагрузку; после записи следует запрашивать обратное чтение/verify.
- Стандартные STK500v1 команды fuse *записи* и запрограммированные SPI-последовательности типа `AC A0` **не исполняются**, ответ `00` — как в обычном Optiboot.

Для теста на реальной плате (после установки загрузчика через ISP-программатор):

```bash
# Порт выберите под свою систему: /dev/ttyUSB0, /dev/ttyACM0, COM3 и т.п.
avrdude -p m328p -c arduino -P /dev/ttyUSB0 -b 115200 -U eeprom:r:backup.bin:r
# ТОЛЬКО ЧТЕНИЕ fuse, если ваша версия avrdude поддерживает эту операцию через bootloader
avrdude -p m328p -c arduino -P /dev/ttyUSB0 -b 115200 -U lfuse:r:-:h -U hfuse:r:-:h -U efuse:r:-:h
```

**Перед изменением flash/EEPROM сохраняйте резервную копию, не меняйте fuse-биты без проверки платы, сохраняйте доступ по ISP для восстановления.** Данный HEX нельзя загружать по адресу 0x0000 в секцию приложения; его адрес назначения 0x7E00, нужен 512-байтный boot-раздел (например, для обычного Arduino Uno HIGH fuse `0xDE`, при условии подходящей аппаратной схемы).

## Выполненные проверки

- Реальная компиляция Clang AVR backend и `llvm-objcopy`: ELF без внешних релокаций, 506 байт инструкций, 2 байта версии, 4 байта `FF` в зазоре, полный 512-байтный бинарник.
- Выполнение **собранных AVR-машинных инструкций** на ограниченном Python-интерпретаторе `test_eeprom.py`: **598 корректных командных обменов** плюс отрицательные тесты (включая полную EEPROM, запись/verify Flash, ошибочный EOP, адрес за пределами EEPROM и неполные пакеты).
- `test_universal.py`: **24 чтения fuse/lock**, **762 запроса неизвестных функций**, проверка блокировки ISP-записей, нормальной работы EEPROM и Flash после чтения fuse, и ошибочного EOP. Периферийная модель требует `BLBSET|SPMEN` перед `LPM` и сбрасывает этот режим после чтения.
- `test_differential_upstream.py`: **556 команд** из старого набора с идентичными ответами UART и содержимым пользовательской Flash по сравнению с оригинальным Optiboot HEX. `SET_PARAMETER` намеренно не участвует в этой дифференциальной проверке: оригинал воспринимает её как неизвестную команду без аргументов, а наша сборка корректно принимает два аргумента.
- **НЕТ** физической платы в доступе, фактического теста UART/avrdude, настоящей проверки аппаратного SPM/LPM/EEPROM таймингов или частоты ошибок передачи. Не использовать в критичных устройствах без ISP-восстановления и проверки.
