# Optiboot ATmega328P: 368 байт и машинное сравнение с оригиналом

**Дата:** 28 октября 2026 г.  **Статус:** экспериментальный загрузчик — проверен в собственном эмуляторе AVR, **не на физическом микроконтроллере**.

Оригинал: <https://github.com/Optiboot/optiboot>  
С: <https://github.com/Optiboot/optiboot/blob/master/optiboot/bootloaders/optiboot/optiboot.c>  
Даташит ATmega328/P, раздел 30.8: <https://docs.arduino.cc/resources/datasheets/Atmel-42735-8-bit-AVR-Microcontroller-ATmega328-328P_Datasheet.pdf>.

## Размер

| Вариант | Инструкции/код | Версия | Занято (без FF-заполнения) | Сохранено от официального HEX |
| --- | ---: | ---: | ---: | ---: |
| Официальный `optiboot_atmega328.hex` из GitHub | 472 | 2 | **474** | — |
| Наша первая версия (ошибка с WDT!) | 408 | 2 | **410** | 64 |
| **`optiboot_mini328_final`** — рекомендуемый для тестирования | **366** | 2 | **368** | **106 (22,36%)** |
| `optiboot_mini328_final_tiny` — без заглушки API | **364** | 2 | **366** | **108 (22,78%)** |

Оба итоговых Intel HEX адресуют **0x7E00–0x7FFF** (512-байтная область загрузчика) с версией `03 08` по адресам `0x7FFE–0x7FFF`. Пустое место заполнено `0xFF`. BIN всегда имеет длину 512 байт; его нельзя писать без смещения по адресу 0.

**Честность сравнения:** официальный бинарник, на котором измерено 474 байта, включает LED-индикацию и вызываемый из приложения SPM-сервис; в наших версиях эти функции намеренно исключены. Экономия **не** равна оптимизации при идентичных дополнительных возможностях. К примеру, `NO_APP_SPM=1` и `LED_START_FLASHES=0` позволяют существенно уменьшить сам оригинал. Feature-matched оригинал в данной среде не пересобран (нет `avr-gcc`/`avr-libc`).

## Ключевая оптимизация

В ATmega328P аппаратный временный буфер программирования Flash можно **заполнять до стирания страницы** (вариант 1 из раздела 30.8 даташита):

1. Считать UART-данные и сформировать слова в аппаратном SPM-буфере.
2. Проверить `CRC_EOP` и ответить `STK_INSYNC=0x14`.
3. Только после успешной проверки выполнить `Page Erase` (`SPMCSR=0x03`).
4. Записать аппаратный буфер `Page Write` (`0x05`), дождаться завершения.
5. Восстановить чтение RWW (`0x11`) и ответить `STK_OK=0x10`.

Это **не** использует 128-байтовый буфер SRAM. При повреждённом EOP старая страница не стирается. Даташит прямо разрешает последовательность «fill → erase → write» и описывает её как один из двух вариантов обновления Flash. Модель эмулятора поддерживает сохранение данных аппаратного буфера после стирания страницы и очищение его после Page Write; соответствие реальному чипу нужно подтвердить аппаратно.

## Обнаруженные и исправленные ошибки

- **WDT был выключен!** В первой версии при запуске загрузчика ставился `0x06`, а при выходе `0x00`. Для ATmega328P правильные `WDTCSR` — `0x0E` (WDE + WDP2 + WDP1 = 1 с) и `0x08` (WDE = 16 мс). Благодаря этому при отсутствии UART загрузчик запускает приложение после watchdog reset.
- **UART FE0.** Как официальный Optiboot, новая версия не выполняет `WDR`, когда полученный байт имеет framing error (FE0), чтобы некорректный поток не задерживал выход в приложение.
- **Обработка EEPROM WRITE.** Пакет `PROG_PAGE 'E'` сначала принимается полностью; EOP подтверждается `INSYNC`, затем происходит зависание до WDT 1 с — как в официальном HEX. Первая наша версия аварийно прекращала приём раньше.
- **Чтение длины.** Для ATmega328P официальный Optiboot игнорирует старший байт длины, используя младший. Теперь так же. Если `READ_PAGE` имеет длину 0, официальный бинарник возвращает 256 байт; наш тоже.
- **Сокращены переходы** (`BRxx` вместо `BRxx+RJMP` там, где хватает дальности), объединено отбрасывание полей `SET_DEVICE`, `SET_DEVICE_EXT`, `UNIVERSAL`; устранён повторный `MOVW` перед записью Flash. Выход в адрес 0 осуществляется через `RJMP` на конец 32-КБ Flash с переполнением PC, как у оригинального Optiboot.

## Совместимость протокола

Результаты представлены в **`PROTOCOL_AUDIT_RU.md`**. `differential_test.py` запускает **машинные инструкции** официального GitHub HEX 8.3 и нашей сборки в одном тестовом интерпретаторе AVR, посылая одинаковые запросы. Проверено по 575 командных обменов на каждый финальный вариант (2556 входных байт), включая все 256 значения команды за вычетом команд с аргументами, все 256 вариантов GET_PARAMETER, рандомизированные команды, типовую и частичную прошивку страниц, высокие байты длины и чтение с длиной 0. Протокольные ответы совпали побайтно; содержимое программной Flash после записи совпало.

Тесты также сравнили 9 комбинаций MCUSR, реакцию на FE0, ошибочный CRC_EOP, неподдерживаемую EEPROM WRITE, состояние WDT и запрет стирания boot-раздела. Все тесты пройдены.

**Это не доказательство полной идентичности для всех 256^N последовательностей** и не физический тест UART/SPM/WDT. Оставлены осознанные отклонения (см. аудит), включая проверки неверной длины и запрет записи boot-страниц.

## Сборка

Нужны Python 3, Clang с AVR backend, `llvm-objcopy`, `readelf`; AVR-LibC не требуется:

```bash
python3 build.py optiboot_mini328_final optiboot_mini328_final_tiny
python3 test_emulator.py
python3 differential_test.py
python3 test_invariants.py
```

`test_emulator.py` — функциональные AVR-инструкционные тесты; `differential_test.py` — сравнение с оригинальным HEX; `test_invariants.py` — проверка инструкций SPM непосредственно после `OUT SPMCSR`, WDTCSR-последовательности, версии и защиты boot-раздела.

Сценарий `download_upstream.sh` скачивает репозиторий Optiboot для изучения C-кода, если доступен GitHub.

## Прошивка на плату

Только **ATmega328P, 16 МГц, UART0 115200**, boot-секция **512 байт** с началом по `0x7E00`; у типовой Uno `HFUSE=0xDE`, но перед изменением обязательно проверить существующие фьюзы и lock-биты конкретной платы. Не применять эти HEX для других ATmega/ATtiny, ATmega4809 и плат с частотой 8 МГц.

Рекомендуется заранее прочитать и сохранить дамп Flash и фьюзов через ISP. Для записи HEX нужен ISP-программатор, например USBasp; перед работой проверить адрес загрузчика и реальную конфигурацию платы. Восстановление ошибочного загрузчика возможно через ISP:

```bash
# Осторожно: пример записи через ISP; avrdude может стирать прикладную прошивку!
avrdude -c usbasp -p m328p -U flash:w:optiboot_mini328_final.hex:i
```

После проверки на запасной плате проверить `avrdude -c arduino -p m328p -b 115200 -P /dev/ttyACM0`, чтение сигнатуры, полную запись/verify, автосброс и отсутствие зависания при неправильной скорости UART. **Изменять фьюзы и lock-биты без предварительной проверки не следует.**

## Файлы

- `optiboot_mini328_final.{S,hex,bin}` — рекомендуемая исследовательская версия, 368 байт, с заглушкой `RET` на boot+2.
- `optiboot_mini328_final_tiny.{S,hex,bin}` — версия 366 байт без `RET` на boot+2. Приложение, вызывающее старый Optiboot SPM API, несовместимо с обеими.
- `upstream_reference.hex` / `upstream_reference.bin` — эталонный бинарник из официального репозитория; `upstream_reference.bin` развёрнут в 512 байт и требуется дифференциальным тестам.
- `original_mini_410B_broken_WDT.S` — прошлая версия для сравнения. **Не прошивать**: в ней ошибка конфигурации watchdog.
- `CHANGES_vs_410B.patch` — подробное сравнение ассемблера со старой версией.
- `test_*.py`, `differential_test.py`, `build.py` — воспроизводимая сборка и эмуляция.
