# Optiboot Mini 328 — исследование уменьшения загрузчика

**Состояние:** исследовательская сборка от 28.10.2026. AVR-машинный код собран, протокол и запись Flash проверены в небольшом *самостоятельном программном эмуляторе*. **На реальной Arduino Uno/ATmega328P ещё не проверено** — не использовать для единственной доступной платы без возможности восстановления по ISP.

## Размеры на ATmega328P

| Сборка | Используемые байты кода | Версия | Итого (не считая `0xFF`-заполнения) | Экономия против исходного готового HEX |
|---|---:|---:|---:|---:|
| Официальный `optiboot_atmega328.hex` | 472 | 2 | 474 | — |
| **`optiboot_mini328` (буферизованная)** | **408** | **2** | **410** | **64 (13,5%)** |
| `optiboot_mini328_stream` (потоковая) | 400 | 2 | 402 | 72 (15,2%) |

В каждом варианте `.hex` и `.bin` покрывают **512 байт** по `0x7E00–0x7FFF` (ATmega328P, 256 слов boot). Неиспользуемое заполнено `0xFF`, а последние два байта содержат версию `03 08`, соответствующую 8.3. «Размер кода» — конец последней инструкции перед заполнением, измеренный из символа `_code_end`.

**ВНИМАНИЕ О СРАВНЕНИИ:** официальный готовый HEX собран с миганием LED при старте и с сервисом app-callable SPM. В наших вариантах обе возможности **отключены**. Поэтому разность 64/72 байта **не является** чистым выигрышем ассемблерной оптимизации при одинаковой функциональности. Для честного сравнения можно пересобрать официальный исходник с `LED_START_FLASHES=0 NO_APP_SPM=1` (см. ниже); такой сборки в данном архиве нет. Дополнительные сокращения нашего кода (объединение подпрограмм, близкое размещение обработчика ошибки, переиспользование X) проверены отдельно.

## Что реализовано

- UART0, 115200 8N1, F_CPU=16 МГц; U2X0=1, UBRR0=16 (фактически ~117647 бод, +2,12%).
- STK500v1: `GET_SYNC`, `GET_PARAMETER` (SW major/minor), `SET_DEVICE`, `SET_DEVICE_EXT`, `ENTER_PROGMODE`, `LOAD_ADDRESS`, `UNIVERSAL`, `PROG_PAGE`, `READ_PAGE`, `READ_SIGN`, `LEAVE_PROGMODE`; INSYNC/OK фрейминг.
- Режим обычного Optiboot: вход в загрузчик по внешнему RESET без WDRF (либо MCUSR=0), запуск приложения при POR и WDRF, сохранение исходного MCUSR в `r2`.
- WDT 1 с при ожидании, 16 мс при выходе/ошибке.
- Запись Flash через SPM с erase→fill→write→RWWSRE, чтение Flash через `LPM`.
- Защита от прямой записи начиная с 0x7E00, отказ от EEPROM. Размер программы — не более одной Flash-страницы за запрос (до 128 байт), запись по 2 байта за раз.

## Чем пожертвовали

- Нет мигания LED.
- Нет чтения/записи EEPROM (как и в обычном базовом Optiboot без расширения).
- Нет сервиса `do_spm` по адресу boot+2: вместо него `RET`. Приложения, которые вызывают Optiboot SPM API, **несовместимы**.
- Нет программного UART, других частот/MCU, расширенных STK500-команд и записи несоосных страниц. Адреса рассчитаны строго на ATmega328P.
- Внутри команды `PROG_PAGE` проверяется ненулевое, чётное количество байт не более 128. При ошибке загрузчик дожидается watchdog-reset.

## Буферизация vs потоковая запись

`optiboot_mini328.S` (основной вариант) принимает целую страницу в SRAM с 0x0100, проверяет `CRC_EOP`, а **только затем** стирает и записывает Flash. При повреждённом `CRC_EOP` старая страница остаётся неизменённой.

`optiboot_mini328_stream.S` обходится без буфера страницы, читает байты через USART и сразу загружает аппаратный SPM-буфер. Это экономит 8 байт кода относительно основной сборки и до 128 байт SRAM, но **стирает страницу до проверки `CRC_EOP`**. Прерванная передача может разрушить данные страницы. Не рекомендуется как основной загрузчик.

## Сборка и проверка

В среде разработки использованы `clang` 17 с `-target avr -mmcu=atmega328p` и `llvm-objcopy`; внешние заголовки avr-libc не нужны, все регистры в `.S` указаны непосредственно. Межмодульных релокаций нет.

```sh
python3 build.py
python3 build.py optiboot_mini328_stream
python3 test_emulator.py
```

Программный тест выполняет настоящие собранные AVR-инструкции в небольшом интерпретаторе; проверяет ответы STK500, загрузку Flash, чтение назад, защиту boot-области, запуск приложения и повреждённый EOP. **Это не полная модель таймингов, регистров и периферии ATmega328P.** В частности, связь с реальным USB-UART, ёмкостной autoreset, различия экземпляров чипа и физический WDT надо проверять на плате.

Чтобы скачать полный исходник Optiboot и проверить эталон с теми же отключенными функциями:

```sh
sh download_upstream.sh
cd upstream/original_repo/optiboot/bootloaders/optiboot
make atmega328 LED_START_FLASHES=0 NO_APP_SPM=1
```

Если на машине нет GNU AVR-GCC, оригинал не удастся собрать указанной командой. Наши ассемблерные версии можно собрать приложенным `build.py`, если есть Clang AVR backend и llvm-objcopy.

## Прошивка

Адрес загрузчика: `0x7E00`. На **обычной Arduino Uno ATmega328P 16 МГц** используется загрузочный раздел 512 байт, BOOTRST включён, соответствующее значение HFUSE часто `0xDE` (проверить до прошивки). Не использовать эти HEX на ATmega168/2560/8/4809, 8-МГц платах и с другими фьюзами.

Только после успешного теста в эмуляторе + наличия ISP-программатора/резервной копии:

```sh
# Пример для USBasp (SPI/ISP), НЕ для обычной загрузки по UART:
avrdude -c usbasp -p m328p -U flash:w:optiboot_mini328.hex:i
```

Отдельно, при необходимости, **проверить** фьюзы и lock-bits для конкретной платы; без проверки не менять их. Перед прошивкой сохранить дамп текущей Flash/fuses по ISP. После прошивки проверить Arduino IDE/avrdude `-c arduino -p m328p -b 115200`, чтение сигнатуры, программирование и verify, затем autoreset и watchdog-reset.

- Перемещение редко используемых ветвей, сокращение диспетчера STK500v1 и проверок длины без ослабления безопасности.

- Аппаратное тестирование на AVR, включая приём первых байтов сразу после autoreset.
