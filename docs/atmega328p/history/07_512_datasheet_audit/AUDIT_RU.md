# Аудит Optiboot Mini EEPROM + UNIVERSAL (ATmega328P)

**Дата:** 28.10.2026. **Объект:** `optiboot_328_eeprom_universal.S` (оригинал 506 Б кода + 2 Б версии = 508 Б) и исправленный `optiboot_328_verified.S` (510 Б кода + 2 Б версии = 512 Б). **Тип проверки:** исходник, AVR-объект и машинный код, официальные спецификации, прогон ограниченного машинного эмулятора. **Аппаратных тестов ATmega328P нет.**

## Вердикт

- На уровне **штатного набора команд, используемого avrdude `-c arduino` для ATmega328P**, исправленная сборка проходит предусмотренные программные тесты передачи Flash, EEPROM и диагностики fuse/lock.
- На уровне **полной спецификации AVR061/STK500v1** реализация **НЕ полная и НЕ строго идентичная** аппаратному STK500. Это производная Optiboot с совместимым подмножеством.
- Найдена и исправлена **одна спецификационно значимая ошибка**: при Flash Page Write не обеспечивалось требуемое даташитом значение `PCWORD = 0` в `Z`. Теперь приняты только старты Flash-страниц, выровненные на 128 Б. Любой невыравненный адрес отклоняется до обращения к SPM.
- На реальной плате UART, SPM, EEPROM, fuse/lock и watchdog под нагрузкой не проверены. **Не считать прошивку аппаратно аттестованной**.

## 1. Сверка с ATmega328P datasheet

| Стек AVR | Сброс аппаратного SP в RAMEND; операции RCALL/RET и PUSH/POP; `CLI` до EEPROM | 6.5–6.5.1 | Корректно на ATmega328P после reset, где начальный SP = RAMEND; стек реально расходует SRAM |
| SPM: temporary page fill | `R1:R0`, `Z`, `OUT SPMCSR,0x01` сразу `SPM`, адрес +2 | 26.8, 26.8.2 | Верно, заполнение до стирания прямо разрешено |
| SPM: erase / write | `0x03→SPM`, wait, `0x05→SPM`, wait, `0x11→SPM` | 26.8.1, 26.8.3, 26.8.6 | Верно для адреса на границе страницы; **было нарушение Z для произвольных начальных адресов** |

| EEPROM address/data | `EEARL` I/O `0x21`, `EEARH` `0x22`, `EEDR` `0x20` | 12.6.1–12.6.3 (Atmel-42735B/2016) | Верно; диапазон 0–1023 проверяется с учётом длины |

| EEPROM write | `EEPM1:0=00` через `OUT EECR,0`, `EEMPE` и `EEPE` соседними SBI | 12.6.4 (Atmel-42735B/2016) | Верно; две SBI укладываются в четырёхтактовое окно, прерывания запрещены |
| Согласование EEPROM и SPM | перед EEPROM `wait_spm`, после записи ожидание `EEPE=0` перед ответом | 12.6.4; 26.8.8 | Верно в нормальной последовательности команд |

| Watchdog | `MCUSR=0` перед отключением WDE, пара `STS WDTCSR`, интервалы `0x0E`/`0x08` | 10.8–10.9 | Верно для обычных fuse (`WDTON` не запрограммирован) |
| UART0 | U2X=1, RXEN/TXEN, UCSZ0=3 (8N1), UBRR=16 при 16 МГц | 19.3, 19.10 | Верно; фактическая скорость 117647 бод, ошибка +2.12% относительно 115200. Реальная помехоустойчивость не тестировалась |

- Atmel-42735B, «ATmega328/P Datasheet Complete» (2016), **особенно раздел 12.6.1 о EEAR9 и EEAR8**: https://docs.arduino.cc/resources/datasheets/Atmel-42735-8-bit-AVR-Microcontroller-ATmega328-328P_Datasheet.pdf

**Уточнение к документации:** старый automotive datasheet Atmel-7810D на странице 20 содержит внутреннее противоречие в таблице EEARH (рисует только EEAR8, хотя этот же документ указывает 1 КБ EEPROM). В более новых ATmega328/P datasheets однозначно указаны **EEAR9:8** в двух младших битах EEARH, именно так используется `r27` в нашей прошивке. Для EEPROM адреса 0x200–0x3FF полагаемся на исправленную таблицу, а не на ошибочную версию 2015 года.

### Существенная аппаратная ошибка предыдущей сборки

В оригинале 508 Б перед page write было:

```asm
    movw r30, r22    ; Z = произвольный начальный адрес запроса
    ldi  r16, 0x05
    rcall spm_execute_wait
```

Раздел 26.8.3 требует, чтобы в `Z` при Page Write младшие биты адреса **были нулевыми**. Для обычного avrdude, который обращается к началу страницы, условие соблюдается. Но `LOAD_ADDRESS` позволял произвольный чётный адрес, и firmware его не проверяла; переносить ответственность только на программу-хост нельзя.

Исправление (6 байт) до загрузки SPM-буфера:

```asm
    mov  r16, r22
    andi r16, 0x7F  ; page size 128
    brne protocol_error
```

Чтобы сохранить строго 512 Б, удалён старый двухбайтный `RET`-stub у старта загрузчика (`app-callable SPM` уже отсутствовал). Прежним пользовательским прошивкам, которые вызывали нестандартный вход bootloader+2, этот вариант не подходит — такой сервис никогда не предоставлялся нашей минимальной сборкой.

Блоки Flash с невыравненным начальным адресом теперь **отклоняются** (WDT reset, без SPM/erase), а не эмулируется «частичное изменение Flash с сохранением остальной страницы». В стандартном avrdude 128-байтные страницы программируются с выравниванием; короткая последняя страница начинается также с границы страницы.

## 2. Сверка с AVR061 / STK500v1

Документ: https://ww1.microchip.com/downloads/en/AppNotes/doc2525.pdf

| Команда/режим | Наше поведение | Итог |
|---|---|---|
| GET_SYNC `0x30` | `INSYNC,OK` | Совместимо |
| GET_PARAMETER `0x41` | SW_MAJOR=8, SW_MINOR=3, другие=3 | Совместимо с Optiboot/avrdude, не универсальный реальный STK500 |
| SET_PARAMETER `0x40`, SET_DEVICE `0x42`, SET_DEVICE_EXT `0x45` | Принимает данные и EOP, даёт ACK, игнорирует настройку | Совместимо с нормальным avrdude |
| ENTER/LEAVE_PROGMODE `0x50/0x51` | ACK, запуск приложения через WDT после LEAVE | Совместимо с Optiboot |
| LOAD_ADDRESS `0x55` | 16-битное слово `×2`, в том числе для EEPROM | Совместимо с avrdude `-c arduino` на ATmega328P; не универсальная EEPROM адресация оригинального STK500 |
| PROG_PAGE `0x64` F | 2..128 байт, только чётная длина и начало выровнено на 128 Б | Ограниченный набор AVR061, безопасен для стандартного Arduino page write |
| READ_PAGE `0x74` F | Побайтовое чтение LPM, до 256 по младшему байту длины | С некоторыми ограничениями |
| PROG_PAGE `0x64` E | 1..16 байт, буферизация на стеке до EOP, запись по одному байту | Ограничен длиной, стандартная загрузка EEPROM avrdude работает в 16-байтных блоках |
| READ_PAGE `0x74` E | EEPROM через EERE, диапазон 0..1023 | Совместимо для обычных 1..256 байт |
| UNIVERSAL `0x56` | Только четыре комбинации fuse/lock `50/58 xx`; прочие `00` | **Не полная спецификация**: не пересылает произвольные ISP-команды |
| READ_SIGN `0x75` | `1E 95 0F` | Для ATmega328P верно, но сигнатура константная |
| GET_SIGN_ON `0x31` | Только ACK, не строка `AVR STK` | **Не полная AVR061** |
| CHIP_ERASE `0x52` и ISP `AC 80` через UNIVERSAL | ACK / `00`, но **фактического стирания нет** | **Не соответствуют полной AVR061. Использовать `-e` нельзя** |
| READ_FUSE / READ_LOCK отдельными командами | Не реализованы | **Не полная AVR061**; fuse читаются через UNIVERSAL |
| Неизвестная команда, неверный EOP | Не выдаёт штатный STK_UNKNOWN/NOSYNC; неизвестная команда ACK, плохой EOP → быстрый WDT reset | Optiboot-подобная политика, **не полная AVR061** |
| Поле `bytes_high` размера данных | Читается, но игнорируется | **Не полная AVR061**. Корректно только в указанных ограниченных диапазонах. Например, запрос 0x0102 `READ_PAGE` будет обработан как 2 байта вместо 258 |
| Недопустимый `memtype` | Не `'E'` означает Flash | Совместимо с обычным Optiboot, но формально некорректный тип не отклоняется |

Дополнительный риск: `CRC_EOP=0x20` — это **маркер завершения, не CRC**; данные страницы не защищены от тихой ошибки UART. Нужна стандартная последующая проверка `avrdude verify`.

Исходник avrdude, подтверждающий работу блочных EEPROM через `STK_PROG_PAGE/READ_PAGE` и специальную адресацию классического AVR при `-c arduino`: https://github.com/avrdudes/avrdude/blob/main/src/stk500.c (`set_memchr_a_div`, `stk500_paged_write`, `stk500_paged_load`).

## 3. Проверка сборки и тесты

Проверен собранный объект (`clang -target avr -mmcu=atmega328p`, `llvm-objcopy`), Intel HEX и полный 512-байтный BIN. Подтверждён адрес `0x7E00..0x7FFF`, `version=03 08` в `0x7FFE..0x7FFF` и отсутствие незакрытых линкерных релокаций.

- `test_eeprom.py` — 598 обменов (включая запись/чтение всей EEPROM), отрицательные тесты.
- `test_universal.py` — 24 чтения fuse/lock, 762 неподдерживаемых запросов, последующий EEPROM + Flash.
- `test_differential_upstream.py` — 556 обменов с официальным Optiboot HEX, одинаковые ответы UART и содержимое программной Flash.
- `test_strict_datasheet.py` — проверка машинных инструкций с лимитами `SPMCSR→SPM/LPM`, `EEMPE→EEPE`, выравнивание Z при Page Erase/Write для 25 Flash-транзакций, отклонение пяти невыравненных адресов без стирания, EEPROM + fuse тест.
- `test_protocol_limits.py` — исполняемые тесты известных отличий от полной AVR061 (GET_SIGN_ON, CHIP_ERASE, high length byte, неизвестный memtype и др.).

Это тесты на ограниченном Python-интерпретаторе AVR, а не полноценная симуляция аналогового UART, всех таймеров, реальной внутренней энергонезависимой памяти, прерываний и температурных/питающих режимов. Проверки трёх- и четырёхтактовых окон опираются на соседство инструкций в **реально собранном бинарнике**. Реальный микроконтроллер обязательно нужен для окончательного подтверждения.

## 4. Ограничения и рекомендации

1. **Не используйте `avrdude -e` или запись fuse/lock с `-c arduino`:** загрузчик может подтвердить запрос, фактически ничего не сделав. Настройку fuse, lock и настоящий Chip Erase выполняйте через ISP/HV-программатор.
2. Сохраняйте защиту boot-раздела через boot lock bits, если самоперепрограммирование загрузчика не нужно. Программная проверка `0x7E00` не заменяет аппаратную защиту.
3. Настройка устройства: ATmega328P (не ATmega328PB), внешний 16-МГц источник/Arduino Uno, BOOTRST и BOOTSZ для 512-байтной секции, UART0 115200. Для другой частоты нужно менять UBRR и тестировать.
4. Для записи Flash соблюдайте границы 128-байтных страниц; для EEPROM используйте 1..16 байт за пакет и word address из режима `-c arduino`.
5. Включайте проверку записанной Flash/EEPROM чтением назад (`-U flash:v:...` / `-U eeprom:v:...` или штатное verify avrdude). При пропадании питания EEPROM-блок из 16 байт может быть записан лишь частично.
6. Пропадание питания при записи Flash опасно независимо от правильности последовательности команд. Учитывайте BOD, исправность питания и доступ по ISP для восстановления.
7. Сборка на 512 Б **не оставляет ни одного байта резерва**. Для исправления оставшихся протокольных ограничений придётся оптимизировать дополнительно или убрать некоторые функции.
