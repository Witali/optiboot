# Optiboot ATmega328P: дополнительная оптимизация до 358 / 356 / 350 байт

**Дата:** 28 октября 2026. **Статус:** экспериментальный исследовательский загрузчик. AVR-код успешно собран и проверен в программном интерпретаторе инструкций, **на физической ATmega328P не тестировался**.

Оригинал Optiboot: https://github.com/Optiboot/optiboot

Объект оптимизации — собственный ассемблерный вариант, ранее занимавший 368 байт. Оригинальный официальный HEX использован для проверки команд STK500v1, но у него включены дополнительные LED/SPM-функции, отсутствующие в уменьшенных версиях.

## Результаты

| Файл | Инструкции | Версия | Всего занято | Особенности |
|---|---:|---:|---:|---|
| `optiboot_mini328_previous_368.hex` | 366 | 2 | **368** | Предыдущая версия |
| `optiboot_mini328_final.hex` | 356 | 2 | **358** | РЕКОМЕНДУЕТСЯ для дальнейшей аппаратной проверки: полностью настраивает UART, заглушка `RET` на boot+2 |
| `optiboot_mini328_final_tiny.hex` | 354 | 2 | **356** | Как 358, но без двухбайтной заглушки старого SPM API |
| `optiboot_mini328_reset_only_350.hex` | 348 | 2 | **350** | Как 356, но НЕ задаёт регистр `UCSR0C`; **только после аппаратного/WDT сброса**, а не после прямого вызова из приложения с изменённым UART |

Размеры учитывают два байта версии `03 08` в конце раздела по адресу `0x7FFE`. Все прошивки используют 512-байтную область по `0x7E00..0x7FFF`, неиспользуемые байты заполнены `0xFF`. Минимальный BOOTSZ у ATmega328P — **256 слов (512 байт)**: сокращение кода ниже 512 байт **не увеличивает пространство основной программы**.

## Экономия 10 байт относительно 368B без удаления рабочих возможностей

1. `PROG_PAGE`: для счётчика цикла записи теперь повторно используется `r25`. Вместо `mov r19,r25` и `subi r19,2` используется прямой счётчик `r25`: **−2 байта**.
2. Универсальная отбрасывающая процедура `SET_DEVICE`/`SET_DEVICE_EXT`/`UNIVERSAL` различает `UNIVERSAL` по биту 4 исходной команды через AVR `BST`/`BRTC` (T flag). Процедуры UART и `verify_eop` T не трогают: **−2 байта**.
3. Длина Flash-записи проверяется в словах: `LSR r25` одновременно выявляет нечётную длину (C) и нулевую (Z), далее сравнивается с максимальными 64 словами (`CPI r25,65`). **−2 байта**.
4. `LEAVE_PROGMODE` и команды без параметров теперь имеют общий блок `verify_eop` перед `STK_OK`: **−4 байта**.
5. Константа `SPMEN=1` заранее загружается в `r19`, а не заново при каждом слове SPM. **Размер без изменений**; на полной странице на 63 команды `LDI` меньше.

Дополнительные 8 байт у варианта 350: −2 на отсутствие `RET` заглушки, −6 на отсутствие `LDI`/`STS UCSR0C`. Даташит ATmega328P указывает **сбросное значение UCSR0C = 0x06 (8N1)**. Если приложение передаёт управление напрямую в загрузчик, не сбрасывая MCU, и меняло формат UART0, версия 350 может работать неправильно. Поэтому основной вариант — 358.

## Протокол и проверки

`differential_test.py` сравнивает исполнение реальных AVR-инструкций официального Optiboot и компактных версий: **575 командных обменов**, включая все параметры GET_PARAMETER (256), неизвестные команды, команды адресации, разные длины записи и чтения Flash, сигнатуру, `LEAVE_PROGMODE` и типы памяти. Проверяются идентичные байты UART и содержимое Flash.

`test_additional.py` проверяет ещё **198 обменов на каждый вариант**: случайные страницы, чётные длины 2..128 байт, неполные страницы, повторная запись и чтение. При прямом входе из приложения с UCSR0C=0x36 основная версия восстанавливает 0x06, версия 350 оставляет 0x36, т.е. различие воспроизводится.

`test_emulator.py`, `test_invariants.py`: сохранность Flash после неверного EOP, защита boot-области, последовательность SPMCSR→SPM, окно изменения WDTCSR, сброс по MCUSR, watchdog и UART FE0. Протокол совпадает **в пределах тестируемого корректного подмножества**, а не абсолютно для любого битового потока. Смотрите прежний полный аудит.

**Сохраняются намеренные несовпадения с оригиналом:** проверка длины Flash (запрещены 0, нечётные и >128 байт), блокировка boot-страниц, удалённые LED и app-callable SPM, некоторые изменения MCUSR. EEPROM-программирование не поддерживается. Безопасность аппаратной SPM-операции `fill→erase→write` подтверждена документацией Microchip, но **не аппаратным испытанием**. Эмулятор абстрагирует электрические времена, UART и работу Flash, поэтому успешные тесты не гарантируют работоспособность на реальной плате.

## Сборка и тестирование

Нужны Clang с AVR backend, `llvm-objcopy`, `readelf` и Python 3, AVR-LibC не требуется:

```bash
python3 build.py optiboot_mini328_final optiboot_mini328_final_tiny optiboot_mini328_reset_only_350
python3 test_emulator.py
python3 differential_test.py
python3 test_invariants.py
python3 test_additional.py
```

Для проверки/прошивки — **ATmega328P, 16 МГц, UART0 115200 бод, 512-байтная boot-секция**. Не прошивайте на основном устройстве без сохранённой рабочей копии загрузчика и рабочего ISP-программатора. Перед программированием проверить фьюзы, lock-биты и правильный адрес boot-секции; `BIN` начинается с данных области `0x7E00`, а не с нулевого адреса.

## Следующие идеи, которые уже не дают бесплатной экономии

- Дополнительно убрать ~6 байт UART-конфигурации допустимо только если гарантирован **полный сброс перед входом**: так сделана версия 350. Приоритет совместимости — сохранить 358.
- Снятие проверки длины (~10 байт), блокировки boot-секции (~4 байта) или обработки `FE0` (~2 байта) **не рекомендовано**: экономия покупается потерей защиты/поведения.
- Упрощение решения о входе по `MCUSR` может сократить ещё немного кода, но изменит сценарии POR/WDT/EXTRF и запуск пользовательской программы.
- Для очень маленькой прошивки с отдельным собственным загрузчиком лучше радикально сократить набор STK500v1 команд и настроить загрузочную утилиту под свой протокол — обычный avrdude/Arduino IDE перестанет работать без адаптера.
- Свободные ~154 байта оставшегося boot-раздела в варианте 358 логичнее использовать на дополнительные проверки или минимальную поддержку EEPROM, чем экономить их любой ценой: пользовательская flash-программа из-за BOOTSZ всё равно не станет длиннее.
