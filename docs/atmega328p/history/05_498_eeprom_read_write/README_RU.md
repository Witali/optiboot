# Optiboot Mini ATmega328P — EEPROM read/write

Версия от 28 октября 2026. **Экспериментальная прошивка; аппаратно не проверена.**

## Результат

- 496 байт машинных инструкций + 2 байта версии = **498 байт содержимого**.
- Секция загрузчика: строго 512 байт по адресу `0x7E00..0x7FFF`, заполнение неиспользуемых 14 байт — `0xFF`.
- Для сравнения: прежний Optiboot Mini (только Flash) занимал 358 байт вместе с версией.
- Устройство: ATmega328P / Arduino Uno, 16 МГц, UART0 115200 8N1.
- **Flash-прошивка осталась без SRAM-буфера**: используется внутренний временный SPM-буфер.
- EEPROM: добавлено чтение и запись по стандартным `STK_READ_PAGE` / `STK_PROG_PAGE` с типом памяти `'E'` (`0x45`).
- **EEPROM запись: 1..16 байт за запрос** с промежуточным SRAM-буфером 16 байт по адресу `0x0100`. Для чтения по STK_READ_PAGE допускаются 1..256 байт (низкий байт длины 0 трактуется как 256, как в исходном коде Optiboot).
- Стандартный avrdude `-c arduino` для classic AVR отправляет EEPROM блоками по 16 байт. Для этого не нужно менять ПК-инструменты.
- SRAM для EEPROM чтения не нужна; стек AVR работает отдельно.
- Программная защита от обращения к EEPROM за пределами адресов `0..1023` (включая переполнение длины блока).
- `STK_GET_PARAMETER`, `STK_SET_DEVICE`, `STK_SET_DEVICE_EXT`, `STK_LOAD_ADDRESS`, `STK_UNIVERSAL` (заглушка `00`), `STK_PROG_PAGE`/`STK_READ_PAGE` (Flash), `STK_READ_SIGN`, `STK_LEAVE_PROGMODE` сохранены. `SET_PARAMETER` добавлено как корректный разбор 2 байтов без изменения параметров.
- Мигание LED, запись fuse/lock и вызываемый приложением SPM-сервис не поддерживаются.

## Форматы команд (STK500v1)

`STK_LOAD_ADDRESS`: `55 low_word_address high_word_address 20` -> ответ `14 10`.

Для **ATmega328P + `-c arduino`** avrdude передаёт *слово-адрес* даже для EEPROM. Например, для EEPROM byte-address `0x0200` надо передать `word_address=0x0100`, т.е. `55 00 01 20`. В загрузчике обе памяти используют `address * 2` из LOAD_ADDRESS. Поэтому **отдельный нечётный начальный адрес EEPROM выбрать нельзя**, но 16-байтовый блок охватывает все байты, в том числе нечётные.

Запись EEPROM: `64 00 10 45 <16 байт данных> 20` -> ответ `14 10`.

Чтение EEPROM: `74 00 10 45 20` -> ответ `14 <16 байт данных> 10`.

Для Flash в этих же командах используется тип `F` (`0x46`).

`0x20` называется в протоколе `CRC_EOP`, но **не является контрольной суммой**. Он проверяет конец пакета, а не целостность переданных данных. Для обнаружения незаметных искажений используйте команду верификации avrdude.

## Безопасность EEPROM-записи

1. Проверяются размер 1..16, стартовый адрес и последний адрес пакета (не выше 1023).
2. Все данные загружаются в SRAM `0x0100..0x010F`.
3. Проверяется завершающий `CRC_EOP=0x20`.
4. Ожидается окончание Flash `SELFPRGEN/SPMEN`, затем перед каждым байтом — `EEPE`; выбирается атомарный режим стирания+записи `EEPM1=EEPM0=0`.
5. Выполняется пара `SBI EECR,EEMPE; SBI EECR,EEPE` (обязательное аппаратное окно 4 такта).
6. Последняя запись завершена до `STK_OK`.

Если EOP отсутствует или неверен, **EEPROM не изменяется**, загрузчик сбрасывается по watchdog. Если питание пропадёт **после** принятия корректного пакета, но посреди 16 байтов, частичная запись возможна: пакет **не является транзакцией**. Старые значения EEPROM также не сравниваются с новыми: повторная запись приводит к износу.

## Файлы

- `optiboot_328_eeprom_rw.S` — AVR ассемблер, полноценный исходник.
- `optiboot_328_eeprom_rw.hex` — Intel HEX для ISP-программирования. Адреса `0x7E00..0x7FFF`.
- `optiboot_328_eeprom_rw.bin` — ровно 512 байт для boot-секции (включая заполнение `0xFF`).
- `build.py` — повторяемая сборка с Clang AVR backend и `llvm-objcopy`, `readelf`.
- `avr_base_sim.py`, `test_eeprom.py` — ограниченный AVR-интерпретатор и EEPROM-периферия для тестов машинного кода.
- `optiboot_mini328_358.bin` — предыдущее машинное изображение для дифференциальной проверки Flash/STK500.
- `upstream_reference.bin` — бинарник официального Optiboot, предоставленный из предыдущего этапа разработки.
- `eeprom_test16.bin` — демонстрационный 16-байтовый файл (изменяет EEPROM адреса 0..15, если записать на устройство).
- `test_output.txt` — протокол проведённых программных тестов.
- `COPYING` — GPL-2.0-or-later, производная работа от проекта [Optiboot](https://github.com/Optiboot/optiboot).

## Сборка

Требуется Clang с поддержкой `-target avr`, `llvm-objcopy`, `llvm-objdump` и `readelf`:

```bash
python3 build.py optiboot_328_eeprom_rw
python3 test_eeprom.py
```

Скрипт проверяет отсутствие внешних релокаций, что код укладывается в 510 байт без двух байт версии, длину бинарника 512 и адреса HEX. Тесты исполняют скомпилированные AVR-инструкции; не являются реальным моделированием аналоговой части UART и длительностей EEPROM/Flash.

## Как проверить на реальной плате

**Требуется ISP-программатор для установки экспериментального bootloader и восстановления, если он не запустится.** Убедитесь, что установлена 512-байтная boot-секция с началом `0x7E00`, включён `BOOTRST` и кварц 16 МГц. Для обычного Arduino Uno типичный HIGH fuse `0xDE`; не меняйте fuse без отдельной проверки текущей конфигурации.

После прошивки загрузчика ISP и подключения USB-UART (с DTR/RESET) выполните, заменив порт `/dev/ttyUSB0` на реальный:

```bash
# Сначала резервная копия EEPROM!
avrdude -p m328p -c arduino -P /dev/ttyUSB0 -b 115200 -U eeprom:r:backup_eeprom.bin:r

# Пробный файл 16 байт: изменит адреса EEPROM 0..15.
avrdude -p m328p -c arduino -P /dev/ttyUSB0 -b 115200 -U eeprom:w:eeprom_test16.bin:r -U eeprom:v:eeprom_test16.bin:r

# Проверка чтением всей EEPROM.
avrdude -p m328p -c arduino -P /dev/ttyUSB0 -b 115200 -U eeprom:r:readback_eeprom.bin:r
```

Не прошивайте этим HEX секцию приложения по адресу `0x0000`. До аппаратной проверки рекомендуется сохранять доступ по ISP. Тестовую запись 16 байт **не делайте** на плате с важным содержимым EEPROM без резервной копии.

## Проверки и ограничения

Пройдены **598 корректных командных обменов**, плюс отрицательные тесты; в их числе 64 записи по 16 байт и обратное чтение всех 1024 байт EEPROM, 15 неполных блоков, чтение 256 байт, проверка Flash и 268 дифференциальных обменов относительно старой 358-байтной сборки. Проверки ошибок EOP, укороченного пакета, переполнения EEPROM и неверной длины не вызвали записи EEPROM в эмуляторе.

**Важно:** реального теста на ATmega328P/AVRDUDE не было. Эмулятор неполный, временные характеристики EEPROM, watchdog, UART и SPM не проверены на оборудовании. Поэтому бинарник экспериментальный.

Источник описания EEPROM-последовательностей: Atmel/Microchip *ATmega328P Datasheet*, раздел EEPROM, в частности EECR, EEMPE/EEPE, ожидание SPM и режим EEPM. Режим адресации/блоков проверен по `avrdudes/avrdude` `src/stk500.c`.
