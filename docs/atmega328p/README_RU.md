# Экспериментальная прошивка Optiboot для ATmega328P

Прошивка оптимизирована с помощью искусственного интеллекта. Исследование
объединяет оптимизацию AVR Assembly с добавлением функций EEPROM и диагностики
fuse/lock-битов в пределах загрузочного раздела размером 512 байт.

Целевая платформа: ATmega328P / Arduino Uno, 16 МГц, UART0 115200 бод, 8N1.
Актуальный исходник —
[`optiboot_328_verified.S`](../../optiboot/bootloaders/optiboot_328p/optiboot_328_verified.S).
Образ занимает адреса `0x7E00..0x7FFF`: 510 байт инструкций и два байта версии
`03 08`. Свободного места в этом загрузочном разделе нет.

## Что добавлено и оптимизировано

По сравнению с ранними минимальными прототипами этого исследования добавлены
следующие функции и проверки:

| Функция | Возможности и ограничения |
|---|---|
| Запись EEPROM | Команда STK500v1 `PROG_PAGE` с типом памяти `E`: запись всей EEPROM объёмом 1024 байта пакетами по 1..16 байт. Пакет временно хранится в стеке AVR. Граница диапазона и конец пакета проверяются до изменения EEPROM. |
| Чтение EEPROM | Команда `READ_PAGE` с типом `E`: чтение адресов 0..1023 с проверкой диапазона. Длина задаётся младшим байтом; нуль означает 256 байт. |
| Чтение fuse/lock-битов | Через `UNIVERSAL` доступны low, high и extended fuse, а также lock bits. Это диагностическое чтение; запись fuse/lock и произвольные ISP-команды не реализованы. |
| Экономия SRAM при программировании Flash | Данные поступают в аппаратный буфер страницы SPM. Отдельный SRAM-буфер на 128 байт не нужен; рабочий стек по-прежнему расходует SRAM. |
| Проверки записи Flash | До выполнения SPM проверяются выравнивание начального адреса на 128 байт, чётная длина 2..128 байт и защита загрузочного раздела от программной записи. Невыровненные запросы отклоняются до стирания страницы. |
| Обработка ошибочного обмена | Проверяется конец пакета до изменения памяти; недопустимые длины и адреса EEPROM отклоняются. Сохранены watchdog-выход и обработка ошибки кадра UART. |

Сохранены синхронизация STK500v1, загрузка адреса, чтение и запись Flash,
чтение сигнатуры ATmega328P и переход к приложению через watchdog.
В этой реализации отсутствуют стартовое мигание светодиода и сервис SPM,
вызываемый приложением.

Оптимизация позволила вместить расширенный набор функций в 512 байт.
Текущий образ больше некоторых ранних минимальных вариантов: сравнение размеров
и принятых решений приведено в
[истории исследования](research/02_CHANGELOG_HISTORY_RU.md).

## Статус проверки

Проверки используют ограниченный программный интерпретатор AVR и исполняют
сохранённый машинный код. Они охватывают EEPROM, fuse/lock, регрессии Flash,
556 сравнительных обменов STK500v1 с приложенным оригинальным Optiboot и
проверки последовательностей инструкций. Испытания на реальной ATmega328P
и через реальный USB–UART ещё не проводились.
При импорте исходник пересобран, BIN/HEX совпали с архивом побайтно, все пять
наборов тестов прошли на новом BIN. См. [протокол проверки](VALIDATION_2026-10-28.md).

Реализовано подмножество STK500v1. Полное соответствие AVR061 не заявляется:
`GET_SIGN_ON` возвращает только ACK, Chip Erase подтверждается без стирания,
старший байт длины игнорируется, неизвестный тип памяти трактуется как Flash.
Не используйте `avrdude -e` и запись fuse/lock через этот загрузчик.
Подробности находятся в [аудите](current/AUDIT_RU.md),
[описании протокола](research/03_PROTOCOL_AND_HARDWARE_RU.md) и
[плане аппаратных испытаний](research/06_HARDWARE_TEST_PLAN_RU.md).

## Запуск из репозитория

Python 3.10 или новее; запуск пяти актуальных наборов тестов на приложенном BIN:

```sh
python scripts/atmega328p/run_tests.py
```

Пересборка и тестирование полученного BIN требуют `clang` с backend AVR,
`llvm-objcopy`, `llvm-objdump` и `readelf` в `PATH`:

```sh
python scripts/atmega328p/run_tests.py --build
```

Если версия LLVM оставляет локальные релокации, дополнительно нужен `avr-ld`
из `binutils-avr`. Скрипт разрешает релокации без изменения компоновки исходника.

В каталоге загрузчика также доступны `make` для сборки, `make check` для
проверки приложенного образа и `make test` для пересборки с тестами.
В Windows сборку можно выполнять внутри WSL при наличии перечисленных
инструментов в Linux-окружении.

Результаты пересборки помещаются в
`optiboot/bootloaders/optiboot_328p/build/`; эта папка исключена из Git.
Архивные образы и объектные файлы при этом не перезаписываются.

Исходники и образы находятся в `optiboot/bootloaders/optiboot_328p/`,
инструменты — в `scripts/atmega328p/`, документы — в `docs/atmega328p/`.
Все 266 файлов передачи, включая семь исходных ZIP, сохранены и перечислены
в [карте импорта](IMPORT_MANIFEST.json). Она связывает старые пути с новыми
и содержит контрольные суммы до и после адаптации инструментов.
Оригинальные документы и списки контрольных сумм сохранены без изменений
и описывают старую структуру архива. Актуальные пути приведены здесь и
в [основном описании](README.md). Архивные задания и запросы к агенту
сохранены как история исследования.
